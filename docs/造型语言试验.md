# 造型语言试验：方块山 / 斜边台地（2026-08-22，未采纳）

起因是一张 RTS 截图：山是**大大小小的方块**堆起来的，每个面的**边角有加亮**。
问题是这套在我们这台相机下成不成立 —— 我们是 **90° 正视 + 40° 俯角**，
而那类游戏几乎都是 45° 斜视。

代码在 `styles/hellrider/experiments/`，怎么跑见那里的 README。

## 结论

**这套语言在 90° 正视下成立，但前提是墙面朝向要散开。**

根因是算得出来的。场景光指向 `(-0.396, 0.766, -0.507)`，
`hr_flat` 把 θ 映射到 12–105° 再分 4 档，于是轴向的盒子只有这么几个值：

| 面 | θ | 档 | 亮度 |
|---|---|---|---|
| 顶面 | 40° | 2 | 0.733 |
| 左墙（−X） | 67° | 1 | 0.467 |
| 后墙（−Z） | 60° | 1 | 0.467 |
| 前墙（+Z，朝相机） | 120° | 0 | 0.200 |
| 右墙（+X） | 113° | 0 | 0.200 |

yaw 0 时相机只看得见**顶面和前墙**，也就是**只有 0.733 和 0.200 两档**，
而且每个盒子都一样 —— 整堆读成 2D 花纹，看不出谁压在谁上面。
45° 斜视的游戏能成立，是因为那时看得见两面墙，凑够三档。

两条出路，都验证过：

1. **把道具转离轴**（yaw 20–70°）。树可以这么做 —— 树冠的方块往各个方向
   支棱，总有侧面露出来。
2. **让平面轮廓带斜边**（30/45/60°），墙仍然垂直。山必须走这条：
   山是矮墩，可见面积大半是顶面，光靠转朝向救不回来。

## 斜边台地的做法

轮廓不是随手画的多边形，而是拿**半平面去切一个大方形**，半平面的法线只从
一组固定角度里取（0/30/45/60/90/120/135/150/…）—— 交出来的凸多边形，
**每条边必然是那几个方向之一**，不会冒出随机角度。
几层叠起来，每层缩小并偏心；墙垂直、顶水平。

调出味道的两个数（第一版是"叠盘子"）：

- **厚薄要拉开**：40% 概率做 0.30–0.55 的薄"台沿"，其余 1.1–1.9 的厚"墙"。
  都一样厚就成了叠盘子。
- **偏心给足**：每层中心偏 ±0.9r，才有"一侧陡、一侧出台沿"的读法。

**边角加亮**试的是倒角（45° 小斜面在分档着色下自然落进更亮的一档，
纯几何、不需要贴图）。有效，而且顺带解决另一个问题：两块顶面等高并排时，
没有加亮就糊成一整片。但倒角把面数顶了 4–5 倍；既然贴图不是禁区，
**走 UV 内描边更划算**。

## 面数

| | tris |
|---|---|
| 现在的平滑低模石头（一整组，一大配两三小） | ~30 |
| 斜边台地，不倒角 | 42–100 |
| 斜边台地，带倒角 | 194–241 |
| 大小不一的方盒，不倒角 / 倒角 | 72 / 264 |
| 均匀体素岩 / 树 | 336 / 408 |

不倒角的斜边台地只有 42–100，比现在贵不了多少，而**生成代码简单得多** ——
没有凸包、没有环上抖动，不需要 `deconcave`（凹折）、`flatten`（并平面）、
面数分级、底面椭圆。今天在平滑低模上花时间最多的那几个问题，
在这套语言里根本不存在。

**角色要另算**：需求文档 §4.1 要 500–1000 同屏、每个 100–300 tris，
倒角很容易超。角色该用不倒角的版本，靠形体的高低差分面。

## 为什么先不采纳

换掉造型语言就等于不再跟 Hellrider 那张参考图了。
现在这套是按实测校准过的（地面明暗、侧/顶比、面在屏幕上的大小），
换语言要重新推一遍。

不过有一点值得记着：**我们的地面本来就是方格、熔岩是方块**，
方块/台地道具其实比现在的平滑低模**更搭**。
