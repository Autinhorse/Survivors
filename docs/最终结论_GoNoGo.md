## 2. C 项：性能数据汇总

### 2.1 最终架构下的开销

| 负载 | 帧时 | 说明 |
|---|---|---|
| 空场景（环境 + 光照 + 水 + 植被） | 0.65 ms | M2 |
| + 1000 敌人（mm-merged，阴影 B） | 1.05 ms | M5 架构 |
| + Level 4 VFX（1000 弹体 / 100 爆炸每秒） | **1.77 ms** | §23 |

**1.77 ms ≈ 565 FPS**。§12 的目标是 1080p / 60 FPS，即 16.67 ms 预算 ——
开发机上只用掉了约 11%。

### 2.2 关键的架构选择及其收益

| 选择 | 收益 | 出处 |
|---|---|---|
| 小兵用 MultiMesh 合并网格 + Shader 动画 | 2000 单位快 **10.4 倍**（10.64 → 1.02 ms） | M5 |
| 机械动画放进顶点着色器而非 CPU | 更新循环快 **32 倍**（3.16 → 0.10 ms / 1000 单位） | M5 |
| 小兵不投真实阴影（用 blob） | 1000 单位省 **24%**（6.07 → 4.64 ms） | M4 |
| **不给每次爆炸开动态光** | GPU 省 **0.61 ms**，约等于整个 Level 4 粒子负载的 3 倍 | §23 |
| 地面草用贴图 + 凹凸而非几何 | 省 **10 万三角形**（占场景的 1/3） | M2 |

### 2.3 瓶颈定位

**几何量从头到尾都不是瓶颈。** 16,000 个单位时 GPU 仅 1.17 ms。
§5 的判断被完整证实：不要为了把 300 面压到 150 面而优化。

真正的成本依次是：
1. **动态光**（唯一让 GPU 显著上升的东西）
2. **draw call 提交**（已被 MultiMesh 解决：2 万 → 约 300）
3. **逐单位 CPU 更新**（已被 Shader 动画解决）
4. 阴影（已用 blob 缓解）

### 2.4 为什么这不等于通过

§11 明确禁止用开发机判断。基于实测可以给一个**有依据的分解**，
而不是笼统的「要去低端机上试」：

- **群体部分**瓶颈是**单线程 CPU**（16,000 单位 GPU 才 1.17 ms）。
  集显笔记本的 CPU 通常不弱，这部分风险相对可控。
- **VFX 部分**是**纯填充率问题**（overdraw、透明层数）。
  RTX 5080 的填充率高到 §15 点名的风险根本压不出来。
  **这是整个 benchmark 里目标硬件差异最大的一项，也是 C 项真正的未知数。**
- 分辨率影响：overdraw 成本与像素数成正比，4K 下 VFX 数字要乘约 4 倍。

## 4. 建议的下一步（按性价比排序）

1. **§21 资产管线验证**（对应 D 项）。
   本地已装 Blender 5.2，测试内容明确：一组 Rock / 一座 Bridge / 一个 Mech，
   走 AI 3D → Blender → Cleanup → 减面 → 统一 Scale/Origin/材质 → GLB → Godot，
   记录每一步耗时。这是四项判据里唯一**零数据**的一项。
2. **目标硬件复跑**（对应 C 项）。成本极低：拷贝项目 + 一条命令，结果自动写 CSV。
   重点看 VFX 等级 2–4 的 GPU 时间，而不是敌人数量。
3. **重叠爆炸的补充压测**。当前爆炸撒在 22 m 半径内，§15 点名的
   「大量重叠爆炸」没被充分复现；真实玩法里爆炸会聚集在玩家周围。
4. **碰撞 / 物理开销测量**。M5 的架构结论建立在「没有碰撞体」之上，
   给每单位加碰撞很可能把 Node 式开销重新引回来 —— 这是采用该架构前的最后一块拼图。
5. 视觉补完：建筑细节、大气层次（A 项的已知短板）。

## 6. 过程中值得留存的工程教训

这些都是「引擎不报错但结果是错的」类型，全部由视觉核对发现：

1. **`.tscn` 的 `Transform3D` 按行序列化**，按列写会得到转置矩阵。
2. **三角形缠绕方向**与 Godot 正面约定相反时，看到的是壳体内壁 ——
   而法线数值检查会显示「正确」，因为法线和缠绕是两回事。
3. **球体两极的顶点必须共用位移**，否则极点三角扇退化、顶面照不到光。
4. **`cull_disabled` 下背面法线会被翻转**，竖直面片会完全不受光。
5. **脚本内部用全局类名调自己的静态函数**会在直接运行时编译失败
   （类缓存只由编辑器构建），表现为进程假死。
6. **`amount_ratio = 0` 会连粒子池一起归零**，`emit_particle()` 静默不发射 ——
   而且测出来的性能数字**比真实情况更漂亮**。
7. **性能测试必须配合视觉核对**。第 6 条是最危险的一种失败：
   一个没有真正产生负载的压测，读数一样好看。
