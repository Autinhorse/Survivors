# 环境表面制作方法

M2 视觉验证过程中摸出来的一套做法，记下来供正式做场景时复用和继续优化。
所有数字都是在本项目机位下实测的，换机位要重算（见 §5）。

**前提**：固定俯视机位（60°、高 44 m、FOV 40），1600×900 下约 **29 像素/米**；
低多边形 + 程序化生成为主；Godot 4.7 Forward Mobile。

---

## 1. 三层分工

做"表面看着不平"这件事，容易一上来就想到贴图，但实际是三件不同的事，
用错层次会白费力气：

| 层 | 负责什么 | 用什么做 |
|---|---|---|
| **轮廓** | 这东西的外形对不对 | 几何。轮廓错了，贴图救不回来 |
| **过渡** | 面与面之间是硬棱还是渐变 | 几何（倒角）。着色器做不出侧影 |
| **表面** | 同一个面内部的花纹与受光 | 着色器程序化 + 法线扰动 |

判断顺序也是这个顺序。本项目里"河岸太规则"其实是**轮廓**问题（挖槽曲线太光滑），
"河岸太平"是**过渡 + 表面**问题，两者要分开治。

---

## 2. 过渡：地形边缘倒角

### 结论：用 `CSGPolygon3D` 的旋转扫掠，别叠圆柱

叠一圈圈更宽更浅的圆柱做台阶 —— **原理上做不出倒角**。
圆柱是等半径的，每一级必然留下一个水平台面：

- 3 级 → 读成梯田
- 7 级 → 读成灯芯绒

台阶数量再多也只是把平行条纹变密，不会变成斜面。

正确做法是把倒角的**剖面**画出来，绕轴转一圈：

```python
node("RiverLip%d" % i, "CSGPolygon3D", ter,
     {"polygon": "PackedVector2Array(...)",   # (半径, 高度) 的折线
      "mode": "1",                            # 1 = MODE_SPIN
      "spin_degrees": "360.0", "spin_sides": "20",
      "smooth_faces": "true", "operation": "2"},
     T(centre))
```

剖面本身是斜的，转出来就是连续斜面，不存在台阶。

### 地面之间的高差：高度场，别用旋转的盒子

桥头引桥这类"从地面堆上去"的过渡，用旋转的 CSG 盒子会同时犯三个错，
而且都是原理性的：

1. 三面都是硬棱 —— 侧面和坡趾读成一个三角楔子，一眼是几何体不是地形；
2. 它是实体，会捅穿旁边的东西（本项目捅穿了桥面，也捅穿了一栋房子）；
3. 布尔运算的结果没法渐隐进周围地面。

改成**四周平滑归零的高度场网格**（`scripts/environment/EarthRamp.gd`）一次解决三条：

```gdscript
var ramp := smoothstep(0.0, 1.0 - head_flat, u)      # 纵向，两端导数为 0
var side := 1.0 - smoothstep(1.0 - side_falloff, 1.0, absf(v))
var h := height * ramp * side
h += noise(...) * noise_amp * ramp * side * head_fade
return h - sink * (1.0 - side)                        # 边缘略沉，防 z-fighting
```

三个细节，少一个都会露馅：

- **噪声必须被同一个包络乘住**，否则边缘会翘起一圈毛边；
- **顶端也要把噪声收掉**（`head_fade`）—— 桥底面离坡顶只有十几厘米，
  噪声在这里顶起 0.1 m 就会从桥板缝里冒出来；
- **用地形材质**。`ground.gdshader` 是世界坐标投影的，土丘的草地纹理会和
  周围地面严丝合缝；换成 UV 投影立刻出现接缝。
  坡度还会自动触发着色器的草→土→石过渡，坡面比平地更偏土色，
  正是踩出来的路该有的样子。

### 手摆的大件要做占位检查

60° 俯视下，"前后错开几米"和"真的重叠"在截图里长得几乎一样 ——
本项目里桥和房子的穿模就是靠算才发现的，肉眼一直以为只是挨得近。

`gen_greybox.py` 的 `check_clearance()` 用轴对齐包围盒算两两间距，生成时打印。
两条使用要点：

- **`allowed` 列出本来就该贴在一起的组合**（引桥土坡和桥面端头），
  否则真问题会淹没在预期内的报告里；
- **渐隐类的东西按"实际起作用的那一块"登记**，不是整个包围盒 ——
  高度场在边缘已经归零，拿整块外框判定会把周围一大片都判成冲突。

它的价值在于当场抓到你**刚引入**的问题：本项目里两次挪房子，
两次都是它立刻报出新的重叠。反过来说，**检查表漏一项，检查就等于没做** ——
第一版漏登记了土坡，于是求解出来的房屋位置"避开了桥"，却正好落在坡里。

### 剖面要照顾每一处标高

一处外扩只能给一个标高的地面做倒角。本项目两岸标高不同
（近岸 y=0、远岸高台 y=+2），所以剖面里做了**两处外扩**。
正式场景里有几级台地，剖面里就要有几处外扩。

### 粗细分工

- **水线轮廓**：步长 0.9 m 的圆柱挖槽。这是细节，也是岸边浪花 UV 的依据，不能粗。
- **岸口倒角**：又宽又软，扫掠用 2.0 m 步长就够，省一半节点。

### 顺带的好处

45° 左右的斜面正好落在地形着色器 `slope_rock..slope_grass` 的过渡区间里，
草会自然地爬下岸口一小段，而不是齐刷刷断在棱上 —— 过渡是"免费"多出来的。

## 3. 表面：世界坐标程序化，不是法线贴图

### 为什么不用 StandardMaterial3D 的法线贴图

**它在程序化网格上会静默失效。** `bmesh.ops.convex_hull` 和 CSG 都不产生 UV，
Godot 没有 UV 就生成不了切线，法线贴图既不报错也不生效。
这条路在这个管线里基本走不通。

### 用什么代替

在着色器里按**世界坐标**取噪声，并从噪声梯度**自己算法线扰动**。
不需要 UV、不需要切线，对 CSG 和程序化网格天然适用。

三次取样拿到高度和梯度，在**表面自身的切平面**里推法线：

```glsl
vec3 n = normalize(w_nrm);
vec3 th = cross(vec3(0.0, 1.0, 0.0), n);
float tl = length(th);
th = tl > 0.001 ? th / tl : vec3(1.0, 0.0, 0.0);   // n 竖直时退化，要兜底
vec3 tv = normalize(cross(n, th));

vec2 uv = vec2(dot(w_pos, th), dot(w_pos, tv)) * scale;
float h0 = texture(noise, uv).r;
float hx = texture(noise, uv + vec2(eps, 0.0)).r;
float hy = texture(noise, uv + vec2(0.0, eps)).r;

ALBEDO = base * (1.0 - contrast * 0.5 + contrast * h0);
vec3 pn = normalize(n - (th * (hx - h0) + tv * (hy - h0)) * bump);
NORMAL = normalize((VIEW_MATRIX * vec4(pn, 0.0)).xyz);
```

**在切平面里推、不是在世界 XZ 里推** —— 后者会把斜面上的纹理拉扁。

投影方式：建筑这种全是平面四边形的，用**切平面平面投影**就够，
比三平面混合便宜，也没有混合带的模糊；相邻面坐标系不同会有缝，
但那里本来就是硬棱，看不出来。曲面（地形、石头）才需要三平面。

### 噪声选型

| 想要的读法 | 噪声 |
|---|---|
| 一般粗糙表面 | 值噪声 / 分形（`noise_type` 默认） |
| **一块块石头** | **元胞噪声** `noise_type=2`, `cellular_return_type=4`(Distance2Sub) |
| 草叶的丝缕 | 脊形分形 `fractal_type=2` |
| 层理（岩壁） | 值噪声，UV 竖向拉伸 4-5 倍 |

值噪声只有各向同性的斑点，**出不来"一块块"的读法** —— 河岸立面必须用元胞噪声。
石块那一层不要竖向拉伸，拉长了就成了木纹。

## 4. 一个材质，一次 draw call

需要"同一个物体上不同部件不同颜色"时，**把颜色烘进顶点色**，
在 Blender 侧合并成单一材质：

```python
def bake_materials_to_vcol(obj, material="Surface", coarse=()):
    # 读每个材质槽的 Principled Base Color（已经是线性的），
    # 按 polygon.material_index 写进 CORNER 域的 BYTE_COLOR，
    # 然后 materials.clear() + 挂一个白色载体材质
```

好处有三个，第三个最容易被忽略：

1. 8 个材质槽 → 1 个，每栋房子从 8 次 draw call 降到 1 次；
2. Godot 侧可以**整体挂一个 material_override**，而不会把各部件冲成同一个颜色；
3. GLB 实例如果不挂 override，用的就是 Blender 里的纯色材质 ——
   生成器里精心配的 `MAT["wall"]` / `MAT["roof"]` **根本没作用到它们身上**。
   这个坑在本项目里踩了两次（树、房屋），两次都表现为"改参数完全没反应"。

`COLOR.a` 是免费的一个通道，用来给着色器选参数组
（本项目：0 = 石/灰泥，1 = 木/茅草；植被里则是 0 = 实体木头，1 = 叶片贴片）。

**注意色彩空间**：Blender 的 Principled Base Color 是**线性**的，
而 Godot 的 `albedo_color` 是 sRGB。手写调色板时要 `srgb_to_linear()`，
从材质节点读则已经是线性、不要再转。

## 5. 判据与尺度换算

### 判据

**同一块平面内部、去掉光照低频之后的亮度起伏**（std / 均值）。

整块区域的 std 不能用 —— 它主要反映光照梯度和阴影，不是表面有没有材质。
先用 9 像素均值滤波取出高频再统计。

```
python tools/surface_detail.py shot.png --ref docs/target.png \
    --region 屋顶 195,110,265,165 --ref-region 屋顶 250,60,350,120
```

本项目当前状态（比值 1.0 = 与参考图一致）：

| 表面 | 参考 | 现在 | 比值 |
|---|---|---|---|
| 屋顶 | 15.0% | 14.7% | 0.98 |
| 墙面 | 19.2% | 16.2% | 0.84 |
| 河岸立面 | 17.1% | 17.0% | 1.00 |

### 尺度换算（必算，别凭感觉填）

噪声特征在屏幕上的尺寸：

```
特征(像素) = px_per_metre / (noise_frequency × texture_size × scale)
```

本项目 `detail_noise`（freq 0.035、256 px）、29 px/m：**特征(px) = 3.24 / scale**

```
python tools/surface_detail.py --scale-table --noise-freq 0.035 \
    --texture-size 256 --px-per-metre 29
```

| scale | 特征(px) | |
|---|---|---|
| 0.50–0.75 | 6.5–4.3 | **合适** |
| 1.5 | 2.2 | 太细 |
| 2.2 | 1.5 | 被抗锯齿平均掉，等于没做 |

**4–7 像素**是这个机位下的甜区：再细会被平均掉，再粗会读成豹纹。
本项目在这上面栽过两次 —— 一次填 2.2 导致"加了纹理反而更平"，
一次填 0.55 但对比度给到 0.34 导致屋顶变豹纹（尺度是对的，错在对比度）。

## 6. 需要透光的东西：alpha 裁剪贴片

树冠、灌木这类**中间要透光**的，实体几何做不到，这是原理性的
（试过光滑球体和凸包叶簇堆积，都是"一坨"）。做法是细枝干（真几何）
+ 挂在枝上的四边形贴片，采样图集做 **alpha 裁剪**。

裁剪而不是混合：走不透明通道，不排序、阴影自动正确、没有透明层填充开销。

**代价在填充率不在三角形**：三角形少了 6%，帧时反而涨 11%
（early-Z 失效 + 贴片层叠）。集显是填充率受限的，这个比例很可能更大 ——
正式项目要按距离降贴片数量做 LOD。

## 6.5 外部贴图：程序化生成的物体也能用

**能。** 程序生成不等于只能用程序化纹理 —— 缺的只是 UV，补上就通了。
桥已经跑通这条路，可以直接照抄。

### 四步

1. **在 Blender 侧铺 UV。** 程序生成的网格默认没有可用 UV：
   `bmesh` 建的完全没有，`primitive_*` 的每个面都铺满 0..1（尺度不一致，
   大小不同的木件纹理密度会差好几倍）。
   `uv_planar()` 按**局部坐标做平面投影**，也就是"按米铺"：

   ```python
   uv_planar(o, uv_scale=0.30, offset=(rng.uniform(0, 4), rng.uniform(0, 4)))
   bevel_edges(o, width=bw)      # 顺序要紧：先 UV 后倒角
   ```

   每个面按法线主轴投影到另外两轴，**两轴里较长的那个给 U** ——
   于是木纹自动顺着板、梁、柱的长边走，不用逐件指定方向。
   `offset` 给每件一个随机位移，否则所有木件纹理一模一样。

   顺序不能反：倒角会新增面，那些面从相邻面**插值**拿 UV；先倒角的话新面没有 UV。

2. **导出。** glTF 自动带上 `TEXCOORD_0`，Godot 导入即用。
   检查方法是看 GLB 里 primitive 的 attributes —— 本项目里
   `rocks_lp.glb` / `pebbles.glb` 就是没有 `TEXCOORD_0` 的反例。

3. **图片放 `assets/textures/`，就是普通 PNG。**
   `tools/gen_textures.py` 只负责给一版能用的初始内容，
   之后用任何画图软件改，或者整张换掉。改完重新导入即可，不用碰代码：

   ```
   Godot_v4.7-stable_win64_console.exe --path . --import --headless
   ```

   平铺密度在 Godot 侧调（`uv_tex_scale`），不用改图。

4. **着色器按 UV 取样。** `shaders/prop.gdshader` 的 `use_uv_tex=1` 那一路。

### 一个关键设计：按贴图自身的平均色归一化

```glsl
vec3 tex = texture(albedo_tex, UV * uv_tex_scale).rgb / uv_tex_mean;
ALBEDO = mix(base, base * mix(vec3(1.0), tex, uv_tex_strength), use_uv_tex);
```

`uv_tex_mean` 由生成器从 PNG 算出来填进去，**必须在线性空间算** ——
PNG 存的是 sRGB，在 sRGB 空间求平均会偏亮，归一化之后木头整体发暗。

这样贴图**只贡献偏离平均的部分** —— 花纹、结疤、你画上去的脏污和磨损 ——
整体色调仍由顶点色控制。好处：

- 一张木纹图能长出深浅不同的所有木件（顶点色管色调，贴图管花纹）；
- 你把整张图调暗一档，场景里的木头**不会**跟着整体变暗，改动可预期；
- 想让贴图颜色完全说了算时，把 `uv_tex_strength` 调到 1、`uv_tex_mean` 设成白色。

### 什么时候值得上外部贴图

| 情况 | 用什么 |
|---|---|
| 大面积、各向同性的粗糙表面（地面、岩壁、灰泥） | 世界坐标程序化，不需要 UV |
| **有方向性 / 重复结构**（木纹、瓦片、砌缝、布纹） | **外部贴图 + UV** |
| 手绘的独特细节（招牌、标记、特定位置的磨损） | 外部贴图 + **有意设计的 UV 布局** |

最后一种要注意：`uv_planar` 给的是按米的平面投影，适合**可平铺**的材质，
画不了"这个角落有块补丁" —— 那需要为资产设计一套确定的 UV 图集布局
（每个部件占已知的一块矩形），并导出一张 UV 参考图供你对着画。
这一步本项目还没做，见 §7。

## 7. 还没做、正式项目要补的

1. **手绘定位图案的 UV 布局**：招牌、标记、特定位置的磨损。
   可平铺材质那条路已经通了（§6.5，桥的木纹就是），
   但那是按米的平面投影，画不了指定位置的图案。
   需要为资产设计确定的 UV 图集布局，并导出 UV 参考图。
   属于需求文档 §21 点名的管线缺口。
2. **房屋和地形还没铺 UV**，仍是纯程序化。要上木板走向、瓦片排列，
   照 §6.5 给它们加 `uv_planar` 即可。
3. **LOD**：贴片植被按距离降数量；地形倒角的扫掠精度按距离降。
4. **集显验证**：所有性能数字都来自 RTX 5080 Laptop。
   填充率相关的结论（贴片、alpha 裁剪、着色器取样数）在集显上要重测。
5. **碰撞体**：本轮完全没测。倒角剖面变复杂之后碰撞体应该用简化版，
   不要直接用渲染网格。

## 8. 踩过的坑（速查）

| 现象 | 真正的原因 |
|---|---|
| 改材质参数完全没反应 | GLB 实例没挂 `material_override`，用的是 Blender 里的材质 |
| 法线贴图拉 10 倍也没反应 | 程序化网格没 UV → 没切线 → 法线贴图静默失效 |
| 法线贴图很弱 | `NoiseTexture2D.bump_strength` 默认是 8，被调到了 1.4–2.4 |
| 加了纹理反而更平 | 尺度填太细（1.5 px），被抗锯齿平均掉 |
| 屋顶变豹纹 | 尺度对，对比度太高 |
| 倒角变梯田 / 灯芯绒 | 叠圆柱必然留水平台面，要用旋转扫掠 |
| 岸壁像块平板 | 岩石分支没有法线扰动，拿到的是 CSG 插值出的光滑几何法线 |
| 植被一片纯白 | glTF 导出 `export_vertex_color` 默认 `"MATERIAL"`，顶点色没导出 |
| 岸边浪花消失 | 判据坐标（UV.x 归一化）和实际可见范围对不上（**踩了三次**） |
| 一整片纹理是灰的 | 特征做成了亚像素尺寸 |
| 贴了外部贴图后整体偏色 | 没按贴图自身平均色归一化，贴图的色相乘进了顶点色 |
| 倒角后新增的面没有贴图 | UV 要在倒角**之前**铺，新面靠插值继承 |
| 拉索/杆件斜穿物体 | 用了只在 XY 平面算的线段变换，而物件绕 Y 轴转过 |
| 引桥像个三角楔子 | 旋转的 CSG 盒子三面都是硬棱，要改成四周归零的高度场 |
| 手摆的大件穿模 | 没做占位检查；俯视角下错开几米和真重叠长得一样 |

最后一条值得单独说：**这些坑里有一大半，第一反应都是"渲染路径不支持"或者
"参数还得再调"，实际都是别的原因。** 判断卡住的时候，做一个能区分两种假设的
对照实验（比如把法线图换成已知可见的普通噪声），比继续调参快得多。
