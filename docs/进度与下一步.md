## 明天的第一件事：用格子做明暗

（你的想法，我先把接口位置找出来放在这儿，明天直接动手。）

现有的格子只用在**地面**上：`shaders/hr_ground.gdshader` 里

```glsl
vec2 cell = floor(w_pos.xz / tile_size);   // tile_size = 2.6 m
// 用 cell 的哈希取一个亮度档，tile_steps / tile_bias 控制档数和偏向
```

可能的挂接点：

- **道具也吃同一套格子**。`shaders/hr_flat.gdshader` 现在完全不看世界位置，
  可以按 `floor(w_pos.xz / tile_size)` 取同一个哈希，给整个物体（或整个面）
  叠一点亮度偏移 —— 物体和它脚下的地面就属于同一"格调"。
  注意：**要按物体原点取格，不是按片元取**，否则一个物体会被格线切开。
- **更大的分区**。参考图真正拉开画面的是**大块的地形色块**（不同区域不同底色），
  尺度远大于一格。可以在格子之上再套一层低频（比如 `floor(w_pos.xz / (tile_size*6))`），
  用它选底色，格子只负责细的明暗。这条直接对应待办里
  "安静块 56% vs 参考 61-70%"和"更大的地形色块分区"。
- **`hr_ground` 已经留了 `path_mask` 接口**，还没接遮罩图。土路可以走这条。

要注意的既有约束（都在 README 里，别踩回去）：

- hellrider **不许有贴图和法线扰动**，格子明暗必须是程序算出来的
- 明暗**必须分档**，不能是连续渐变
- 我们是**正方轴向**世界，格线水平竖直 —— 今天的教训就是格子一旦被
  "看见"（石头底边贴格线）就会和背景同频，读成一堆盒子。
  用格子做**明暗**和用格子做**形状**是两回事，前者参考图里到处都是，后者不行。

## 今天走过但否决的路

规则本身是从参考图里读出来的，实现也做出来了（1x1 / 1x2 / 1x3 / 2x2 / 2x3 /
