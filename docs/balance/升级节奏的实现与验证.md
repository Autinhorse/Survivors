# 升级节奏：从一句话反推出全套数值

2026-08-27。设计意图（讨论中确定）：

> 前面的枪满级了，但一枪打不死当前的主要小怪，需要两枪；
> 合并成新一代，DPS 翻倍，又能一枪一个；
> 小怪血量继续涨、枪慢慢升到 2、3 级，又变成两枪；再合并……

## 一、写成公式后它自己闭合

```
换代那刻：单发伤害 D = 靶子血量 H × α（锚点系数）
升到 3 级：D → D×k（k ≈ 1.33）
靶子血量涨过 D×k                → 两枪一个
合并：DPS 翻倍，新单发 D' = 2×D×k → 又是一枪一个
```

一代之内靶子血量涨 **2k ≈ 2.66 倍**，武器单发也涨 2.66 倍——两边自动同步。
代入血量成长 1.21/周期：

```
一代 = log(2.66)/log(1.21) = 5.1 个周期 = 6.8 分钟
四代 = 21 个周期 = 27.4 分钟
```

**现有的血量成长 1.21 正好对应"4 代 / 27 分钟"的目标局长——这个数一直是对的。**
前面几轮在它身上折腾都是错的方向。

## 二、三条线用同一条规则生成

> 单发伤害 = 该线主打敌人在该阶段的血量 × 锚点系数 α
> 换代涨幅 = 2 × 同种内涨幅（正好对应"合并 DPS 翻倍"）

| 线 | 主打靶子 | α | 效果 |
|---|---|---|---|
| 机枪 | 小怪 | 1.4 | 代初一枪一个，代末两枪，合并后回到一枪 |
| 单发 | 重甲 | 1.4 | 同上，但靶子是重甲 |
| 散弹 | 小怪 | 0.6 | 始终两三枪才死一个，靠 AoE 一次打多个 |

**α = 1.0 时节奏不会振荡**（换代那刻正好一枪，下一刻血量就涨过去，之后永远两枪）。
抬到 1.4 才留出代初 2-3 个周期的"一枪一个"。

## 三、节奏验证：四次完整振荡

```
周期 2-4   机枪 lv1→lv2     一枪一个
周期 5-7   机枪 lv2→lv3     两枪一个   ← 打不死了，该合并了
周期 8     重机枪 lv1        一枪一个   ← 合并，回到一枪一个
周期 10-12 重机枪 lv2→lv3    两枪一个
周期 13    加特林 lv1        一枪一个   ← 再合并
周期 15-17 加特林 lv2→lv3    两枪一个
周期 18    加特林阵列 lv1     一枪一个
周期 20-21 阵列 lv2→lv3      两枪一个
```

四次振荡覆盖 21 个周期 ≈ 28 分钟，和推演一致。

## 四、测试工具换代：LadderTest

是死于"该合并了但不能合并"，不是死于配平。

新的 `demos/03_balance/LadderTest.gd` 让炮塔**按时间表自动换代升级**
（一代 5.1 周期，代内匀速升到 3 级），测的才是"这套曲线本身站不站得住"。

| build | 平均存活 | 推到第几波 | 终局武器 |
|---|---|---|---|
| **纯机枪线** | **593.5s** | 98 | 重机枪@3 |
| 纯散弹线 | 311.0s | 47 | Spread Gun@3 |
| 混合 3机枪+3散弹+2单发 | 343.8s | 64 | Rifle@1 |
| 混合 4机枪+2散弹+2单发 | 210.6s | 34 | Rifle@1 |

**节奏成立了，分工仍然不成立**：纯机枪还是赢，每掺一门单发成绩就掉一截。

## 六、失败原因

看终局武器那一列——所有含单发的 build 都停在 **Rifle@1，一代都没升上去**，
因为它们活不过 5.1 个周期（一代的长度），根本轮不到换代。

单发线的第一代（Rifle）就已经完全应付不了杂兵：

```
Rifle 单发 4066、间隔 2.5 秒 → 0.4 次击杀/秒，8 门 = 3.2 只/秒
第 1 周期杂兵刷新           → 约 3.9 只/秒
                              一开局就在净积累
```

它对重甲一枪一个（设计成立），但重甲每周期 4 只、杂兵每周期 315 只。
**单发线在开局就必须依赖别人清杂兵，而混合也救不了**——
把一半槽位换成"清不动杂兵"的武器，杂兵那条线立刻崩。

现在是 8 门机枪刚好够应付杂兵，**一门都匀不出来**。
要让混合成立，杂兵压力得降到"4 门机枪就够"。这是下一步在扫的参数。

## 七、杂兵数量 15 → 12，混合终于跟上来了

| build | count=15 | **count=12** | 变化 |
|---|---|---|---|
| 纯机枪线 | 593.5s | **781.4s** | +32% |
| **混合 3机枪+3散弹+2单发** | 343.8s | **699.4s** | **+103%** |
| 混合 4机枪+2散弹+2单发 | 210.6s | 547.4s | +160% |
| 混合 4机枪+4单发 | 103.8s | 322.8s | +211% |
| 纯散弹线 | 311.0s | 330.0s | +6% |
| 纯单发线 | 79.5s | 80.8s | 持平 |

纯机枪 vs 最佳混合的差距从 **1.7 倍缩到 1.12 倍**。更关键的是终局武器：
count=15 时所有含单发的 build 都卡在 Rifle@1，count=12 时能推到
**Marksman Rifle@3 / Shotgun**（第 3 代）——它们终于活得够久，节奏跑得起来了。

`base.count` 是**每波生成数量的基准**，不是同屏上限：

```
该波生成数量 = base.count × 数量成长^(周期-1) × 该波型形状系数
```

count=12 时第 1 周期各波：12 / 18 / 18 / (重甲 4) / 24 / 30 / **120** / 30，
一个周期（80 秒）共 256 只，刷新 3.2 只/秒。同屏实际数量取决于杀怪速度，
实测峰值中位在 100-400 之间（强 build 能堆到 800+）。

## 八、扫描脚本的一个隐患（已修）

超时被 kill 时 `finally` 不执行，`data/*.json` 会留在污染状态——
上一轮 `sweep_swarm` 超时后 `base.count` 被留在了 5.0。
现在四个扫描脚本都加了 `.sweepbak` 备份 + 信号处理 + 启动时自动还原残留。
