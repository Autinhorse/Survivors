# 三条枪线的分工为什么还不成立

2026-08-27。设计意图（来自讨论）：
**机枪清小怪、单发杀大怪、散弹击退辅助，且不指望单靠一条线过关，要 2-3 种配合。**

这一轮做了四件事，把问题收敛到了一个可以直接计算的算术式。

## 做了什么

1. **机枪线改造**：间隔压到 0.1-0.2 秒、单发伤害相应下调、名义 DPS 保持文档原值。
   浪费从 87-92% 降到 47-62%。
2. **重甲拆成独立威胁轨道**：波次模型扩展成"每波可带自己的 base/growth"，
   重甲不再参与杂兵的总血量平衡（base 2400/4 只，成长 1.30/1.00）。
3. **重甲改成远程后撤炮台**（§4.3 那条"主角靠近会后撤"，之前没实现），
   想用射程差做几何克制：机枪线射程 6-7，单发线 8/10/12。
4. **单发线 DPS ×1.5-2**（只压间隔，单发伤害不动，保留一发毙命的手感）。

## 结果：四条改动加起来，纯机枪还是赢

| build | 名义 DPS | 存活 |
|---|---|---|
| 纯机枪 8 门 | 3,000 | **627.4s** |
| 纯单发 8 门 | 4,571 | 89.8s |
| 纯散弹 8 门 | 448 | 333.2s |
| 混合 3机枪+3散弹+2单发 | 2,436 | 530.1s |
| 混合 4机枪+4单发 | 3,786 | 502.1s |

**混合仍然不如纯机枪。**

## 为什么：一个四倍的缺口

把两个战场分开算：

```
杂兵战场：机枪击杀速率 5.0 只/秒，单发 0.7 只/秒   → 机枪优势 7.0 倍
重甲战场：单发 571 DPS，机枪 375 DPS              → 单发优势 1.52 倍
战场份额：杂兵 47%，重甲 53%

机枪的加权优势 = 7.0 × 0.47 = 3.27
单发的加权优势 = 1.52 × 0.53 = 0.81
                             ↑ 差 4.0 倍
```

**这就是纯机枪打赢一切的全部原因。** 单发在自己的主场只领先 1.52 倍，
而机枪在它的主场领先 7 倍——主场再大也补不回来。

## 沿路验证掉的几个假设

- **提高单发 DPS 没用**：从 2560 提到 4571（+78%），纯单发存活 89.7 → 89.3s，**一点没动**。
  单发对杂兵的表现和 DPS 完全无关，它被"每发只杀一个"卡死在击杀速率上。
- **加重甲血量对机枪没用**：打厚甲目标机枪也不浪费，3000 DPS 全额生效。
  重甲轨道不是"给单发的舞台"，只是一块"取消浪费的场地"，
  而在无浪费的场地上胜负纯粹看 DPS。
- **射程差做不成硬克制**：炮台钉在原地时机甲直接走近；改成后撤（速度 1.2）后
  机甲速度 2 还是追得上。要让射程差生效，后撤速度得 ≥ 机甲速度，
  但那样它就不是"重甲"了。

## 要让分工成立，只有三条路

缺口是 4 倍，必须从下面三处之一（或组合）补上：

1. **单发对重甲的优势从 1.52 提到 ~6 倍** —— 即单发 DPS 提到机枪的 6 倍。
   代价：单发在杂兵战场会更浪费（无所谓，那本来就不是它的场子）。
2. **机枪对杂兵的优势从 7 倍降到 ~1.8 倍** —— 即机枪射速降回去一些。
   但那会把刚修好的"机枪不浪费"又推回去一部分。
3. **重甲变成机枪真的处理不了的东西** —— 不是靠血量或射程，
   而是靠机制。比如：重甲有伤害阈值（单次伤害低于 X 的攻击完全免疫），
   这样低单发的机枪/散弹对它无效，只有大单发的单发线能破。

第 3 条最干净：它是**几何/机制克制**而不是数值权衡，符合 §4.4 的
"Emergent Counter > Hard Counter"（虽然阈值免疫已经算半个硬克制了），
而且它天然解释了"为什么单发要把伤害堆在一发上"——这正是单发线的设计语言。

# 续：把升级节奏写成一条规则

2026-08-27。设计意图（讨论中确定）：

> 前面的枪满级了，但一枪打不死当前的主要小怪，需要两枪；
> 合并成新一代，DPS 翻倍，又能一枪一个；
> 小怪血量继续涨、枪慢慢升到 2、3 级，又变成两枪；再合并……

## 这个节奏能反推出全套数值

写成公式：

```
换代那刻：单发伤害 D = 当前小怪血量 H       → 一枪一个
升到 3 级：D → D×k（k ≈ 1.33）
小怪血量涨过 D×k                          → 两枪一个
合并：DPS 翻倍，新单发 D' = 2×D×k          → 又是一枪一个
```

于是**一代之内小怪血量涨 2k ≈ 2.66 倍，武器单发也涨 2.66 倍**——两边自动同步。
再代入血量成长 1.21/周期：

```
一代持续 = log(2.66) / log(1.21) = 5.1 个周期 = 6.8 分钟
四代（第 2→5 列）= 21 个周期 = 27.4 分钟
```

**现在的血量成长 1.21 正好对应"4 代 / 27 分钟"的局长——这个数是对的。**

## 于是三条线可以用同一条规则生成，不用逐个拍数

> 单发伤害 = 该线主打敌人在该阶段的血量 × 系数
> （机枪 1.0 一枪一个 / 单发 1.0 对重甲一枪一个 / 散弹 0.4 要两三枪）
> 换代涨幅 = 2 × 同种内涨幅，正好对应"合并 DPS 翻倍"

按这条重录三条线后，换代涨幅全部落在 ×2.66–2.69，内部完全自洽。

## 但重测暴露了两个问题

**一、节奏没有振荡起来。** 推演显示机枪线从头到尾都是"2 枪一个"，
没有出现"一枪 → 两枪 → 合并 → 一枪"的循环。原因是锚点取了 1.0 倍——
换代那一刻正好 1 枪，但小怪血量下一刻就涨过去了。
**锚点系数要抬到 1.3–1.5**，代初才有几个周期的"一枪一个"。

**二、存活测试工具失效了。** BuildCompare 把炮塔冻结在 1 级，而这套设计的
全部意义在于升级与合并的节奏。8 门机枪@1 死在第 8 周期，是因为它的 48 点伤害
对上了 152 血的小怪——**死于"该合并了但不能合并"**，不是死于数值配平。

| build | 名义 DPS | 存活 |
|---|---|---|
| 纯机枪 8 门 | 1,200 | 608.7s |
| 纯单发 8 门 | 9,293 | 93.1s |
| 纯散弹 8 门 | 61 | 230.7s |
| 混合 4机枪+4单发 | 5,246 | 95.9s |

单发线 DPS 从 2,560 一路提到 9,293（3.6 倍），存活始终 90 秒上下、纹丝不动。

**下一步**：① 锚点系数 1.0 → 1.3-1.5，让振荡出现；
② 测试工具改成"按时间表升级的 build"，否则测不出这套设计。
