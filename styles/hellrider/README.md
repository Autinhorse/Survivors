# 风格 hellrider

参考：`reference/`（Hellrider, BoomBit）。极简平面着色低多边形。

```
python styles/hellrider/assets.py                      # 需在 Blender 里跑，见下
blender --background --factory-startup --python styles/hellrider/assets.py \
    -- --out-dir assets/hellrider/environment
python tools/gen_scene.py --style hellrider            # -> scenes/VisualBenchmark_hellrider.tscn
bash  tools/hr_shot.sh out.png                         # 生成场景 + 渲染 + 量地面明暗
```

## 和 gatling 的关系：方法几乎处处相反

| | gatling | hellrider |
|---|---|---|
| 石头 | 凸包 22–26 点，倒角，按角度平滑 | 凸包 8–10 点，**不倒角、不平滑** |
| 表面 | UV + 方向性贴图 + 三平面 + 法线扰动 | **没有 UV、没有贴图、没有法线扰动** |
| 植被 | 细枝干 + alpha 贴片叶子 | **实体低面球** |
| 直边 | 拆成一件件去破掉 | **直边就是风格本身，保留** |
| 光照 | 夕阳天光 + 深度雾 + 饱和度微调 | 分档着色，**不开雾、不开 glow** |
| 布局 | 蜿蜒河道 + 曲线路网 | **笔直河道 + 轴向方形场地** |
| 材质数 | 17 | **5** |
| 每栋房子 | 约 3900 面 | **80 面** |

所以两个风格**不共用布局**（`layout.py` 各有一份）。共用的是
`tools/tscnlib.py` / `tools/blenderlib.py` / `tools/gen_scene.py` 和全部测量工具。

## 验收指标（`python tools/scene_audit.py`）

参考图之间本身有跨度（褐色区和水/冰区差别不小），所以判据是
**落在两张参考图之间**，而不是对齐某一张：

| 指标 | 水/冰参考 | 褐色参考 | 当前 |
|---|---|---|---|
| p90/p10 | 2.49 | 1.55 | 1.90 |
| 平均饱和度 | 0.71 | 0.59 | 0.69 |
| 亮于 170 % | 5.0 | 1.4 | 4.3 |
| 块内 std 中位 | 4.5 | 5.5 | 5.3 |
| 安静块 % | 70 | 61 | 56 |

只有"安静块"还偏低（画面偏满），下一步要减散布、留更大的空地。

作为对照，gatling 风格同一套指标是 std 中位 **18.7**、安静块 **4%** ——
这两个数字最能说明两种风格根本不在同一个régime 上。

## 相机：正交 + 40° 俯角（都是实测出来的）

**正交。** 量两侧熔岩边界随纵深的收敛：参考图斜率 −0.005 / −0.087 px/行，
基本是 0；我们原来的透视是 +1.062。只有正交做得到"竖直向上不变窄"。

**40° 俯角。** 参考图里石头和树的侧面露得很多、树干看得见，60° 做不到。
三档并排比出来的，见 `pitch_compare.png`。

连带影响（**这是玩法参数，不只是观感**）：
正交下可见纵深 = size / sin(俯角)，60° 是 42.7 m，40° 是 57.6 m；
可见区域是**矩形**而不是透视的梯形，所以屏幕外生成半径的推导简单得多：

    正交 40°   48.1 m   = 矩形半对角线 × 1.1
    透视 60°   54.3 m   = 梯形最远角（gatling，见需求文档 §9）

## 面内渐变：这个风格不是"死平"的

参考图**每个面内部都有明显渐变**，这是我们和它差得最远的一处：

| | 面内 std | 顶→底斜率 |
|---|---|---|
| 参考 绿丛 | 14–26 | −1.02 /px |
| 参考 树冠 | 12–18 | −0.43 /px |
| 参考 石头 | — | −0.48 /px |
| 我们（纯平面着色） | **0.45** | −0.03 /px |

它**不是贴图**，是**烘在模型上的垂直渐变**（顶亮底暗约 ×0.75，见
`assets.py` 的 `vgrad()`）。按整个物体的包围盒算，所以高的树和矮的灌木
各自都有完整的过渡。

面与面之间保持硬边（风格的骨架），面**内部**靠顶点色插值产生过渡 ——
两者不矛盾：硬边来自法线不平滑，过渡来自顶点色。

## 阴影：blob 贴片，不是投影阴影

参考图里树和石头下面是**软的椭圆团块**：居中在物体正下方、没有方向偏移、
边缘非常虚。那不是投影阴影，是贴在地面上的贴片。
实测参考图的影子深度约 **21%**（暗于旁边的地面）。

在分档着色的平面风格里这不只是省性能：真实阴影贴图会把纯色块切出硬边，
和"大片纯色"的读法直接冲突。

实现在 `shaders/hr_blob.gdshader` + `ScatterField` 的 blob 层
（所有散布物共用一层 MultiMesh，一次 draw call）。

**方向光的 `shadow_enabled` 必须关掉。** 开着的话每个物体同时有 blob 和
投影两个影子，一眼就是假的。方向光仍然负责分档着色，只是不投阴影。

三处踩过的坑，都写在着色器里了：

- 用普通 alpha 混合而不是 `blend_mul`。blend_mul 那一版渲染出来是**硬边方块**。
- 剖面**程序生成**，不用贴图。第一版用 `(1-r)^1.7` 再高斯模糊的 alpha 图，
  结果是"渲染了但看不见"：浓的部分正好被物体自己盖住，露在外面那一圈
  alpha 只有 0.08。用常数 alpha=0.8 做对照才定位到 ——
  同一块地面常数 alpha 压到 125，真实贴图只压到 186（未遮挡 193）。
  现在的剖面是反的：**中心到 `core` 半径实心，只有最外一圈虚**。
- 实心区不要正好压在物体轮廓上（`core = 1/BLOB_PAD`），那样边缘太整齐、
  像贴了张纸。实心区要明显小于轮廓、外扩明显大于轮廓
  （`BLOB_PAD = 1.9`，`core = 0.42`），过渡带横跨整个可见范围。

石头的 blob 按**每块石头自己的底面椭圆**摆（二阶矩求主轴），位置和朝向
跟着散布的旋转走，数据由 Blender 端量出来写进 `rocks_footprint.json`。

## 面的明暗：一条规则（法线和光照方向的夹角）

面的亮度**只**由面法线和光照方向的**夹角 θ** 决定，分档，加一点点逐面随机；
外加一条高度封顶。全部在 `hr_flat` 的 `light()` 里，按**世界**法线算。

    t = (θ_hi - θ) / (θ_hi - θ_lo)    // 只把尺子摊在"看得见的那段"上
    t = t + light_jitter * 逐面随机
    t = min(t, low_cap + (1-low_cap) * 面的相对高度)
    亮度 = mix(light_floor, 1, 量化到 light_steps 档)

**为什么是 θ 而不是 `dot`。** `dot` 就是 cos θ，在接近 90° 的地方压得很扁：
朝向差 20° 的两个侧面 cos 只差 0.06，量化之后挤进同一档。θ 是均匀的，
每一档覆盖同样宽的一段朝向。

**θ 区间（12-105°）是这里最要紧的一个数**，它决定了暗面够不够深。

把四档摊在整个半球（0-180°）上是错的。用 `tools/` 里的脚本量过 `rock_big`
在场景光下的 62 个面：

| 档 | 亮度 | 面积 | θ 范围 |
|---|---|---|---|
| 3 | 1.000 | 6.4% | 12-30° |
| 2 | 0.733 | 23.2% | 30-55° |
| 1 | **0.467** | 31.5% | 64-102° |
| 0 | 0.200 | 38.9% | 106-140° |

40° 俯角的相机看得见的面基本止步于 θ ≈ 105°，再往后就朝下了；而最暗那一档
38.9% 的面积里有 33% 是 θ=140° 的**底面**。也就是说**最暗的一档在画面上是
浪费掉的**，可见的暗面只能拿到 0.467 —— 这就是"石头暗面不够深"的根因。

注意这**不是**"那些面差几度没跨过边界"：量过，θ 64-102° 的那些面离档位边界
还有 10-19°，它们是正正当当落在中间档里的。是尺子的量程没对准画面。

收到 12-105° 之后：

| | 侧/顶 |
|---|---|
| 参考图 zone_brown_rocks2 左石 | 0.59 |
| 参考图 zone_brown_rocks2 上石 | 0.72 |
| 我们 0-180° | 0.86 |
| **我们 12-105°** | **0.68** |

上一版这里是个 gamma（把边界往迎光侧挪）。窗口能做到 gamma 做的事，而且是
**可解释的** —— 两个端点就是"最亮的面"和"看得见的最暗的面"，所以 gamma 删了。

**`low_cap` 这条得留着。** 参考图里低处的面确实更暗，而且这件事只能作用在
**光照**上：光是运行时算的，烘进 RGB 的偏置只改反照率，量过 —— 一个朝光的
下部面能比它上面那个背光的面亮 4.28 倍，几个百分点的反照率偏置压不住。
`vgrad` 把每个面在自己那块连通几何里的相对高度烘进 `COLOR.a`。

### 上一版是三条规则，为什么全删了

上一版用 `dot`，然后叠了三条补丁去补 `dot` 的毛病：

1. **半 Lambert**（`light_wrap`）—— 把背光面摊开，因为 `clamp(dot,0,1)`
   会把所有背光面压成同一个值。**θ 天然就是摊开的**，不需要。
2. **档内连续微分**（`face_tilt`）—— 同一档里朝向不同的面再拉开一点点。
3. **`step_weight`** —— 给"相邻面色差要正比于法线差"兜底，限制量化造成的
   非比例跳变。其实只顶用了 20%（跳变仍有 `step_weight` 那么大一份）。

四个版本并排比过（`hr_shot.sh` 各渲一张），量的是大石头的 顶/前侧/下部：

| | 顶面 | 前侧 | 下部 | 侧/顶 |
|---|---|---|---|---|
| 上一版 三条规则 | 211 | 180 | 159 | 0.85 |
| 角度法 纯线性 0-180° | 211 | 192 | 180 | 0.91 |
| 角度法 + 高度封顶 0-180° | 203 | 179 | 158 | 0.88 |
| **同上，θ 收到 12-105°（现在）** | 207 | **141** | — | **0.68** |

前三行数字打平（0.85-0.91，参考图 0.59-0.72），但角度法**面与面的台阶更干脆**
—— 上一版大石头的整个前面糊成一片亮块。真正把 侧/顶 拉到位的是最后那一行，
也就是上面说的 θ 区间。

### 两条踩出来的

**Godot 不许在 `light()` 里 `return`**（"Using 'return' in the 'light'
processor function is incorrect"），而且编译失败在画面上是**静默**的：
材质退回默认白，所有用 `hr_flat` 的东西一起变白模 ——
第一眼会误读成"算法算错了"。要确认编译，跑一次
`Godot ... 2>&1 | grep -i "shader error"`。

**改了 GLB 一定要先让 Godot 重新导入。** 直接跑场景**不会**触发导入 ——
用的是 `.godot/imported/` 里的缓存，源文件更新了也不管。踩过一次：
Blender 那边把石头改完了，渲出来还是旧模型，差点得出"这个改动没效果"的结论。
`tools/hr_shot.sh` 里已经加了 `--headless --import` 那一步。

**逐面随机要用模型空间的法线做哈希。** 平面着色下 `NORMAL` 在一个面上是常数，
拿它哈希就等于逐面，不用往模型里烘任何东西。用**模型空间**的（`vertex()` 里
那个），同一块石头的花纹才不会因为摆放角度而变。

真正的邻面约束仍然在 Blender 端（`face_relax`），那里才有拓扑：邻面允许色差
上限 = `0.03 + 0.60 * 法线夹角/pi`，在**对数域**上做约束松弛。但它现在只能
约束**高度**那一项 —— 烘的时候还不知道这个实例会被转到哪个 yaw，
所以方向性的明暗约束不到。见"已知待办"。

## 石头的形状：不许有又深又窄的凹折（`python tools/hr_concave.py`）

分档着色下，一个**又深又窄**的凹折读出来是一小块突兀的深色：面法线猛地转
过去再转回来，中间夹的那个面掉进最暗的一档，而它太小，读不成"一个面"，
只读成一个脏点。

判据不是"有没有凹" —— 参考图的石头有台阶，台阶也是凹的。判据是**深且窄**：
折角 > 35°，且相邻两面里较小的那个 < 整体表面积的 4%。

| | 凹边 | 深且窄 | 最深 |
|---|---|---|---|
| rock_big 改前 | 13 | 1 | 63.3° |
| rock_block 改前 | 8 | 3 | 122.1° |
| rock_spire 改前 | 9 | 6 | 125.0° |
| rock_twin 改前 | 22 | 6 | 92.5° |
| **六个变体 改后** | 3–17 | **0** | 12–32° |

两处改动：

1. **第三圈的抖动也沿环平滑。** 上环那里 v9 就这么做了，这一圈当初漏了 ——
   各点独立随机，相邻两个一上一下就折出一条谷。
2. **`deconcave()`** —— 和 `face_relax` 同一类的约束松弛：**保留意图，只约束
   病态**。非共面的顶环是故意的（面的朝向要参差，明暗才碎得开），所以不改
   生成规则，只把超出上限的那几条谷沿两面法线的平均方向推出去，迭代到收敛。
   凸的地方一律不动（硬边是这个风格），贴地的顶点锁住（石头得坐在地面上）。

   **面积那一条不能省。** 第一版只看"深"，把宽台阶也一起抹平了，
   大石头的顶从"有台阶"变成一整片流下来的面，结构就没了。

树和灌木不需要这个：它们是几个凸的团拼起来的，量出来本来就是 0。

## 面在屏幕上要够大（`python tools/hr_face_px.py`）

分档着色把面按朝向分成 4 档，相邻两档差 3.7 倍。这在一个**读得出是平面**的
面上是风格；在一个十几像素的碎片上就是脏点。参考图里"每块石头只有 3-4 个
明确的面"说的就是这件事。

相机是正交的，所以一个面在屏幕上多大和距离无关，一个变体一个数：

    屏幕面积 = 三维面积 × 实例缩放² × |n·视线| × (像素/米)²

判据取 **200 px²**（约 14×14）。实例缩放 1.2 下量出来：

| | 可见面 | 太小的 | 占屏幕面积 | 小面跨了几档 |
|---|---|---|---|---|
| rock_block 改前 | 15.1 | 7.5 | 13.3% | 4 |
| rock_block 改后 | **8.8** | **0.8** | **1.9%** | **1** |
| rock_twin 改前 | 40.9 | 26.2 | 24.0% | 4 |
| rock_twin 改后 | **19.9** | **3.0** | **3.7%** | 3 |

改动只有一处：第三环的门槛从 `radius > 0.95` 提到 `> 1.6`。

### 三步减面（都在 `rock()` 里，按这个顺序）

面多而小的后果不只是"碎"：分档着色下相邻两档差 3.7 倍，两个朝向只差十几度
的三角形一旦跨过档位边界就硬差一整档，读出来是脏点 —— 而不是一个面。

1. **边数按尺寸分级**（`sides_for`）。表里的边数当上限，只降不升：
   `< 1.10 m -> 4`，`< 1.70 -> 5`，否则 6。
2. **第三环只给最大的块**（`radius > 1.6`），而且**比上环粗** —— 先均匀抽到
   4 个点。它在屏幕上比上环小得多，点数还一样就必然碎。
3. **`flatten()`** —— 把法线相近的相邻面并成**一个真正的平面**。
   `dissolve_limit` 只是把它们并成 n-gon，而 n-gon 并不平，直接三角化又会
   变回两个不同朝向的面；所以还要**压平**：迭代地把每个面的顶点往它自己的
   最佳拟合平面上挪，一个顶点被几个面共用就取平均。和 `face_relax` /
   `deconcave` 同一类的约束松弛。贴地的顶点只锁 z，x/y 仍可动 ——
   否则贴地那圈的侧面永远压不平，而石头必须坐在地面上。

   角度扫过 20 / 26 / 30 / 34：`rock_big` 的可见面 22.7 / 20.5 / 17.2 / 17.2，
   34° 已无收益，取 **30°**。

逐块的结果（实例缩放 1.3）：

| | 屏幕 px² | 可见面 前→后 | px²/面 前→后 |
|---|---|---|---|
| rock_slab.0 | 11800 | 27.1 → **12.2** | 446 → **969** |
| rock_low.0 | 10900 | 28.4 → **11.8** | 404 → **919** |
| rock_big.0 | 11500 | 21.1 → **17.2** | 538 → 668 |
| rock_twin.0 | 7300 | 11.1 → **8.8** | 707 → 829 |
| rock_spire.0 | 4000 | 8.8 → **6.3** | 500 → 627 |
| 小配石（600–1700 px²） | | 8.6–9.0 → **4.5–7.0** | 82–193 → 89–255 |

**还欠的三处：**

- `rock_big.0` 是唯一没降下来的（17.2 面）—— 它的面朝向差本来就大于 30°，
  再并就要动生成规则了。
- 最小的那几块配石（600–1000 px²，屏幕上才 25×30 像素）仍是 ~100 px²/面。
  它们太小，改边数已经没什么可减的；真要解决得是**让它们更大或更少**，
  那是布局的事，不是造型的事。
- 参考图仍然比我们**更方**：墙近乎垂直、顶是平台加台阶，而我们 `taper = 0.30`
  让侧壁明显内收，读成穹顶多过读成盒子。

## 地面的明暗：两层格子（`python tools/hr_ground_stats.py shot.png`）

判据不能用 `scene_audit.py`：那是整张图，一块石头就能把 std 抬一倍。
`hr_ground_stats.py` 只取画面里几块写死的**空地**，和参考图
`zone_green_open.png` 里同样大小的干净地面同口径比：

| | 总 std | 半幅块均值 std | 亮:暗(p98/p2) |
|---|---|---|---|
| 参考 干净中央 | 5.54 | 3.04 | 1.133 |
| 参考 右上 | 6.12 | 3.93 | 1.188 |
| 我们（做之前） | 3.26 | **1.36** | 1.036 |
| 我们（现在） | 5.9–6.4 | 2.7–4.7 | 1.15–1.17 |

**"半幅块均值 std"那一行才是关键**：它只留下大尺度的变化。参考图的总 std
里有一多半来自"整片地不一样亮"，我们旧版几乎全在细格上 —— 所以缺的不是
格子，是格子**之上**的那一层。于是现在是两层：

    细格   tile_size 2.6 m（屏幕约 76 px）
    分区   tile_size × zone_size_mul = 7.8 m（屏幕约 230 px），zone_weight 占 0.80

分区尺寸是扫出来的：13 m 时一屏只装得下 5x4 个分区，整块空地会落在同一个
分区里（那块的 std 掉到 1.76）；7.8 m 时三块空地的数字才一致。

跨档只动明度，不动色相和饱和度 —— 参考图量出来跨档 H 0.253→0.266、
S 0.386→0.398，基本不变，就是同一色相的几档明暗。

### 三件踩出来的事

**一、"读成棋盘"要靠权重解决，不是靠把格子转成 45°。**
参考图是 45° 菱形，那是等距投影的产物；**我们是正面 90°、正方轴向的世界，
格线就该是水平竖直的**（见下面第 4 条规则）。转 45° 试过一次，是错的。

轴向格子确实容易读成棋盘 —— 但根因是**细格的振幅**，不是格线的角度。
第一版把 a..b 的跨度放大到 3 倍时 `zone_weight` 只有 0.55，细格跟着一起放大
3 倍，于是满屏椒盐。把权重压到 0.80（细格只剩原来那点振幅，放大的部分全给
分区）之后，轴向格子读出来是**不规则的成片**，不是棋盘。

`lattice_deg` 这个 uniform 留着，只是为了让"格线朝向"在代码里是显式的。
**默认 0，不要改。**

**二、分区边界要跟着细格走，不能是直线。**
第一版分区是规整的大菱形，反差拉到 3 倍看，一条笔直的长边横穿整幅画面。
参考图里同一档是几块相邻菱形连成的**不规则一片**。做法是先落到细格上，
给每个细格一个随机偏移，**再**除以 `zone_size_mul`（`zone_jitter`）。
抖太狠（1.5）会把成片打散回椒盐，1.0 刚好。

**三、`zone_tint` 和 `tile_a/tile_b` 不在同一个色彩空间里。**
`tile_a/tile_b` 是 `source_color`，要过一次 sRGB→线性；`zone_tint` 乘的是
已经在线性空间的 ALBEDO。**同样写 0.035，地面落到画面上是 1.12，物体只有
1.034，差 3 倍。** 补上 2.2 次方之后是 0.11。
（`zone_tint` 就是"道具吃地面分区"：物体按自己的**原点**取格 ——
必须按原点，按片元取的话一条格线会把一块石头从中间切开。
`hr_ground` 和 `hr_flat` 里那套取法要逐字相同，否则物体和它脚下的地面
会落在不同档上，反而更乱。）

## 四条不能破的规则

1. **不许有贴图和法线扰动。**（但要有烘进顶点色的垂直渐变，见上） 一旦加上，纯色块的读法立刻消失。
   gatling 那一整套（§3 的世界坐标程序化、三平面、法线扰动）在这里全部关掉。
2. **明暗必须分档。** `hr_flat` / `hr_ground` 的 `light_steps` 把 N·L 量化。
   连续的 Lambert 会让画面"软"下来，风格就散了。
   地面的两层格子同理（`tile_steps` / `zone_steps`），见上面"地面的明暗"。
3. **不开 glow、不开雾。** bloom 会给纯色块镶光晕，白色小兵直接变成发光的团。
4. **世界是正面 90°、正方轴向的，地面全平。** 场地、河道、方格铺地、色格
   全部沿轴，不做 45° 菱形旋转；地面没有坡，明暗只是反照率，不是高度。
   参考图的菱形是**等距投影**的产物，不是美术选择 —— 照抄角度就等于照抄了
   一台我们没有的相机。这条已经踩过两次：网格石头（`bcfd664` + 其 revert）
   和色格转 45°（`bdb5e72` + 其修正）。原来它只写在 `layout.py` 的开头，
   不在这份清单里，所以放进来。

- 玩家/敌人脚下没有 blob 影子，等做到单位那一步再加。
- **邻面约束管不到方向性明暗**（量过了，先不做）。量化天生违反"相邻面色差
  正比于法线差"：gamma 1.6 / 4 档下档位边界在 θ ≈ 29° / 63° / 104°，
  两个只差 3° 的面跨过边界就硬差一整档（0.267）。片元着色器看不到邻面。

  `tools/hr_face_jump.py` 在网格上量了（绕一圈 72 个朝向取平均）：

  | | 平均\|Δ\| | 超出 face_relax 上限 | 最大\|Δ\| |
  |---|---|---|---|
  | 石头 现在（角度法） | 0.017 | **6.3%** | 0.267 |
  | 石头 上一版（三条规则） | 0.018 | 6.1% | 0.253 |
  | 树 现在 | 0.006 | **2.3%** | 0.267 |
  | 树 上一版 | 0.008 | 2.8% | 0.253 |

  两条结论：**删掉 `step_weight` 没让这件事变糟**（6.3% 对 6.1%，树上还更好），
  那个补丁本来就只顶用 20%；以及绝对量很小 —— 石头上法线差 < 12° 的相邻面对
  占 26%，其中 6.3% 出问题，摊到全部相邻边上是 1.6%。

  真要做，出路是在**生成场景时**烘：石头和树摆下去就不再动了，那时 yaw 已定死，
  可以按最终朝向算完再跑一次 `face_relax`。代价是散布物现在走 `ScatterField`
  → 每个变体一个 MultiMesh 批处理，逐实例烘就要逐实例一份网格，批处理没了。
  折中是把 yaw 量化成几个桶，一个桶烘一份，桶内仍然合批。
  **先不做** —— 1.6% 的边不值这套管线，画面上更缺的是下面那条。
- 河岸那些白石头的下部面被 `low_cap` 压成近黑，读起来像黑白花的。
  白色底色下 `low_cap = 0.30` 太狠了。
- L 型物体的 blob 仍然是一个外接椭圆。真要准得每格一片，
  那样 `ScatterField` 那条路（MultiMesh 一片）也得跟着改。

## 走过但**否决**的路

- **占格子的网格石头**（底面的角落在地面方格顶点上）。参考图能这么做是
  因为它是 45° 等距投影，格线本身是斜的，石头底边贴着格线不抢眼；
  我们是正方轴向世界，格线水平竖直，底边一贴上去就和背景网格同频，
  整片读成一堆盒子。已回退（见 `bcfd664` 与其 revert）。
  如果以后要"石头占格挡路"的玩法，做法应该反过来 ——
  **碰撞体占格，视觉形状不占格**。
