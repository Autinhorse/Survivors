# 风格 hellrider

参考：`reference/`（Hellrider, BoomBit）。极简平面着色低多边形。

```
python styles/hellrider/assets.py                      # 需在 Blender 里跑，见下
blender --background --factory-startup --python styles/hellrider/assets.py \
    -- --out-dir assets/hellrider/environment
python tools/gen_scene.py --style hellrider            # -> scenes/VisualBenchmark_hellrider.tscn
bash  tools/hr_shot.sh out.png                         # 生成场景 + 渲染 + 量地面明暗
```

## 和 gatling 的关系：方法几乎处处相反

| | gatling | hellrider |
|---|---|---|
| 石头 | 凸包 22–26 点，倒角，按角度平滑 | 凸包 8–10 点，**不倒角、不平滑** |
| 表面 | UV + 方向性贴图 + 三平面 + 法线扰动 | **没有 UV、没有贴图、没有法线扰动** |
| 植被 | 细枝干 + alpha 贴片叶子 | **实体低面球** |
| 直边 | 拆成一件件去破掉 | **直边就是风格本身，保留** |
| 光照 | 夕阳天光 + 深度雾 + 饱和度微调 | 分档着色，**不开雾、不开 glow** |
| 布局 | 蜿蜒河道 + 曲线路网 | **笔直河道 + 轴向方形场地** |
| 材质数 | 17 | **5** |
| 每栋房子 | 约 3900 面 | **80 面** |

所以两个风格**不共用布局**（`layout.py` 各有一份）。共用的是
`tools/tscnlib.py` / `tools/blenderlib.py` / `tools/gen_scene.py` 和全部测量工具。

## 验收指标（`python tools/scene_audit.py`）

参考图之间本身有跨度（褐色区和水/冰区差别不小），所以判据是
**落在两张参考图之间**，而不是对齐某一张：

| 指标 | 水/冰参考 | 褐色参考 | 当前 |
|---|---|---|---|
| p90/p10 | 2.49 | 1.55 | 1.90 |
| 平均饱和度 | 0.71 | 0.59 | 0.69 |
| 亮于 170 % | 5.0 | 1.4 | 4.3 |
| 块内 std 中位 | 4.5 | 5.5 | 5.3 |
| 安静块 % | 70 | 61 | 56 |

只有"安静块"还偏低（画面偏满），下一步要减散布、留更大的空地。

作为对照，gatling 风格同一套指标是 std 中位 **18.7**、安静块 **4%** ——
这两个数字最能说明两种风格根本不在同一个régime 上。

## 相机：正交 + 40° 俯角（都是实测出来的）

**正交。** 量两侧熔岩边界随纵深的收敛：参考图斜率 −0.005 / −0.087 px/行，
基本是 0；我们原来的透视是 +1.062。只有正交做得到"竖直向上不变窄"。

**40° 俯角。** 参考图里石头和树的侧面露得很多、树干看得见，60° 做不到。
三档并排比出来的，见 `pitch_compare.png`。

连带影响（**这是玩法参数，不只是观感**）：
正交下可见纵深 = size / sin(俯角)，60° 是 42.7 m，40° 是 57.6 m；
可见区域是**矩形**而不是透视的梯形，所以屏幕外生成半径的推导简单得多：

    正交 40°   48.1 m   = 矩形半对角线 × 1.1
    透视 60°   54.3 m   = 梯形最远角（gatling，见需求文档 §9）

## 面内渐变：这个风格不是"死平"的

参考图**每个面内部都有明显渐变**，这是我们和它差得最远的一处：

| | 面内 std | 顶→底斜率 |
|---|---|---|
| 参考 绿丛 | 14–26 | −1.02 /px |
| 参考 树冠 | 12–18 | −0.43 /px |
| 参考 石头 | — | −0.48 /px |
| 我们（纯平面着色） | **0.45** | −0.03 /px |

它**不是贴图**，是**烘在模型上的垂直渐变**（顶亮底暗约 ×0.75，见
`assets.py` 的 `vgrad()`）。按整个物体的包围盒算，所以高的树和矮的灌木
各自都有完整的过渡。

面与面之间保持硬边（风格的骨架），面**内部**靠顶点色插值产生过渡 ——
两者不矛盾：硬边来自法线不平滑，过渡来自顶点色。

## 阴影：blob 贴片，不是投影阴影

参考图里树和石头下面是**软的椭圆团块**：居中在物体正下方、没有方向偏移、
边缘非常虚。那不是投影阴影，是贴在地面上的贴片。
实测参考图的影子深度约 **21%**（暗于旁边的地面）。

在分档着色的平面风格里这不只是省性能：真实阴影贴图会把纯色块切出硬边，
和"大片纯色"的读法直接冲突。

实现在 `shaders/hr_blob.gdshader` + `ScatterField` 的 blob 层
（所有散布物共用一层 MultiMesh，一次 draw call）。

**方向光的 `shadow_enabled` 必须关掉。** 开着的话每个物体同时有 blob 和
投影两个影子，一眼就是假的。方向光仍然负责分档着色，只是不投阴影。

三处踩过的坑，都写在着色器里了：

- 用普通 alpha 混合而不是 `blend_mul`。blend_mul 那一版渲染出来是**硬边方块**。
- 剖面**程序生成**，不用贴图。第一版用 `(1-r)^1.7` 再高斯模糊的 alpha 图，
  结果是"渲染了但看不见"：浓的部分正好被物体自己盖住，露在外面那一圈
  alpha 只有 0.08。用常数 alpha=0.8 做对照才定位到 ——
  同一块地面常数 alpha 压到 125，真实贴图只压到 186（未遮挡 193）。
  现在的剖面是反的：**中心到 `core` 半径实心，只有最外一圈虚**。
- 实心区不要正好压在物体轮廓上（`core = 1/BLOB_PAD`），那样边缘太整齐、
  像贴了张纸。实心区要明显小于轮廓、外扩明显大于轮廓
  （`BLOB_PAD = 1.9`，`core = 0.42`），过渡带横跨整个可见范围。

石头的 blob 按**每块石头自己的底面椭圆**摆（二阶矩求主轴），位置和朝向
跟着散布的旋转走，数据由 Blender 端量出来写进 `rocks_footprint.json`。

## 面的明暗：三条规则叠在一起

参考图里"亮面成组朝一个方向、暗面成组朝反方向"，而且低处的面更暗。
我们这边靠三件事凑出来，缺一个都不对：

1. **半 Lambert**（`light_wrap = 0.60`）。原来是 `clamp(dot(N,L), 0, 1)`，
   把所有背光面 —— 不管朝 90° 还是 180° —— 压成同一个值，
   一块石头的整个背面是一片死平的色块（量出来只有 2 个色阶）。
2. **档内连续微分**（`face_tilt = 0.10`）+ **`step_weight = 0.80`**。
   后者是给"相邻面色差要正比于法线差"兜底的：`floor()` 量化天生违反这条，
   法线只差 5° 的面跨过档位阈值就硬差一整档，而片元着色器看不到邻面。
   只能限制非比例部分的上限，剩下 20% 严格正比于 N·L 之差。
3. **高度封顶**（`low_cap = 0.30`）。`vgrad` 把每个面在**自己那块连通几何**
   里的相对高度烘进 `COLOR.a`，着色器 `nl = min(nl, low_cap + (1-low_cap)*h)`。
   低处的面再怎么朝光也亮不过这个上限。这是唯一能让"低处更暗"作用到
   **光照**上的办法 —— 烘进 RGB 的偏置只改反照率，压不住一个朝光的下部面
   比背光的上部面亮 4.28 倍。

真正的邻面约束在 Blender 端（`face_relax`），那里才有拓扑：邻面允许色差
上限 = `0.03 + 0.60 * 法线夹角/pi`，在**对数域**上做约束松弛。
约束的对象是面的**最终平均亮度**，不是某一项偏置 —— 只约束自己那一项的话，
`tint` 的逐面抖动照样能让近平行的面差出 0.2 以上。

## 一条反复踩的坑：GLB 节点顺序

`ScatterField` 按 **GLB 里的节点顺序**取变体，而"每变体侧表"
（底面椭圆那类）是我们在 Python 里排出来的。两个顺序对不上，
影子就和石头错位 —— 踩过三次，每次都是渲染出来才看见：

1. 按声明顺序写表，而 glTF 是按名字排的
2. Python 的 `sorted` 是 ASCII 排序，Blender 的是大小写不敏感排序
   （`'L' < 'c'` 对上 `'c' < 'L'`）

现在 `build_rocks` 导出后调 `_check_glb_order` 解析 GLB 核对，不一致直接抛错。

## 地面的明暗：两层格子（`python tools/hr_ground_stats.py shot.png`）

判据不能用 `scene_audit.py`：那是整张图，一块石头就能把 std 抬一倍。
`hr_ground_stats.py` 只取画面里几块写死的**空地**，和参考图
`zone_green_open.png` 里同样大小的干净地面同口径比：

| | 总 std | 半幅块均值 std | 亮:暗(p98/p2) |
|---|---|---|---|
| 参考 干净中央 | 5.54 | 3.04 | 1.133 |
| 参考 右上 | 6.12 | 3.93 | 1.188 |
| 我们（做之前） | 3.26 | **1.36** | 1.036 |
| 我们（现在） | 5.9–6.4 | 2.7–4.7 | 1.15–1.17 |

**"半幅块均值 std"那一行才是关键**：它只留下大尺度的变化。参考图的总 std
里有一多半来自"整片地不一样亮"，我们旧版几乎全在细格上 —— 所以缺的不是
格子，是格子**之上**的那一层。于是现在是两层：

    细格   tile_size 2.6 m（屏幕约 76 px）
    分区   tile_size × zone_size_mul = 7.8 m（屏幕约 230 px），zone_weight 占 0.80

分区尺寸是扫出来的：13 m 时一屏只装得下 5x4 个分区，整块空地会落在同一个
分区里（那块的 std 掉到 1.76）；7.8 m 时三块空地的数字才一致。

跨档只动明度，不动色相和饱和度 —— 参考图量出来跨档 H 0.253→0.266、
S 0.386→0.398，基本不变，就是同一色相的几档明暗。

### 三件踩出来的事

**一、"读成棋盘"要靠权重解决，不是靠把格子转成 45°。**
参考图是 45° 菱形，那是等距投影的产物；**我们是正面 90°、正方轴向的世界，
格线就该是水平竖直的**（见下面第 4 条规则）。转 45° 试过一次，是错的。

轴向格子确实容易读成棋盘 —— 但根因是**细格的振幅**，不是格线的角度。
第一版把 a..b 的跨度放大到 3 倍时 `zone_weight` 只有 0.55，细格跟着一起放大
3 倍，于是满屏椒盐。把权重压到 0.80（细格只剩原来那点振幅，放大的部分全给
分区）之后，轴向格子读出来是**不规则的成片**，不是棋盘。

`lattice_deg` 这个 uniform 留着，只是为了让"格线朝向"在代码里是显式的。
**默认 0，不要改。**

**二、分区边界要跟着细格走，不能是直线。**
第一版分区是规整的大菱形，反差拉到 3 倍看，一条笔直的长边横穿整幅画面。
参考图里同一档是几块相邻菱形连成的**不规则一片**。做法是先落到细格上，
给每个细格一个随机偏移，**再**除以 `zone_size_mul`（`zone_jitter`）。
抖太狠（1.5）会把成片打散回椒盐，1.0 刚好。

**三、`zone_tint` 和 `tile_a/tile_b` 不在同一个色彩空间里。**
`tile_a/tile_b` 是 `source_color`，要过一次 sRGB→线性；`zone_tint` 乘的是
已经在线性空间的 ALBEDO。**同样写 0.035，地面落到画面上是 1.12，物体只有
1.034，差 3 倍。** 补上 2.2 次方之后是 0.11。
（`zone_tint` 就是"道具吃地面分区"：物体按自己的**原点**取格 ——
必须按原点，按片元取的话一条格线会把一块石头从中间切开。
`hr_ground` 和 `hr_flat` 里那套取法要逐字相同，否则物体和它脚下的地面
会落在不同档上，反而更乱。）

## 四条不能破的规则

1. **不许有贴图和法线扰动。**（但要有烘进顶点色的垂直渐变，见上） 一旦加上，纯色块的读法立刻消失。
   gatling 那一整套（§3 的世界坐标程序化、三平面、法线扰动）在这里全部关掉。
2. **明暗必须分档。** `hr_flat` / `hr_ground` 的 `light_steps` 把 N·L 量化。
   连续的 Lambert 会让画面"软"下来，风格就散了。
   地面的两层格子同理（`tile_steps` / `zone_steps`），见上面"地面的明暗"。
3. **不开 glow、不开雾。** bloom 会给纯色块镶光晕，白色小兵直接变成发光的团。
4. **世界是正面 90°、正方轴向的，地面全平。** 场地、河道、方格铺地、色格
   全部沿轴，不做 45° 菱形旋转；地面没有坡，明暗只是反照率，不是高度。
   参考图的菱形是**等距投影**的产物，不是美术选择 —— 照抄角度就等于照抄了
   一台我们没有的相机。这条已经踩过两次：网格石头（`bcfd664` + 其 revert）
   和色格转 45°（`bdb5e72` + 其修正）。原来它只写在 `layout.py` 的开头，
   不在这份清单里，所以放进来。

## 走过但**否决**的路

- **占格子的网格石头**（底面的角落在地面方格顶点上）。参考图能这么做是
  因为它是 45° 等距投影，格线本身是斜的，石头底边贴着格线不抢眼；
  我们是正方轴向世界，格线水平竖直，底边一贴上去就和背景网格同频，
  整片读成一堆盒子。已回退（见 `bcfd664` 与其 revert）。
  如果以后要"石头占格挡路"的玩法，做法应该反过来 ——
  **碰撞体占格，视觉形状不占格**。
- **锥形的树冠团**（`LOBE_SOLO` 里的 `spike`）。拼进多团树冠里读起来像
  插了根东西。代码留着，只给以后做**单团**的针叶树用。
