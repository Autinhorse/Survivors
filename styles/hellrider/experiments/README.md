# 造型语言试验（未采纳，存档）

2026-08-22。起因是一张 RTS 截图（大小不一的方块堆成的山，每个面的边角加亮），
问：这套做山和树是不是更省事？在我们这台 **90° 正视 + 40° 俯角** 的相机下成不成立？

**结论：成立，但必须让墙面朝向散开** —— 要么把道具转离轴（树可以），
要么让**平面轮廓带斜边**（山必须这样）。数字和图见
`docs/造型语言试验.md`。

## 怎么跑

三个脚本都在 Blender 里跑，各自导出一个 glb 到 `assets/hellrider/environment/`：

```
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" \
    --background --factory-startup \
    --python styles/hellrider/experiments/slab_test.py
```

**光导出还看不见**：得把它挂进调参场景才能渲。临时改 `layout.py`：

1. `BIGMAP = False`（回到 `MINIMAL` 调参场景）
2. 在 `_minimal()` 的两句 `put(...)` 后面加一句，比如

   ```python
   put("Slab", "slab_test.glb", 4,
       ((-14.0, -8.0, 1.0, 0.0), (-5.0, -8.0, 1.0, 0.0),
        (4.0, -8.0, 1.0, 0.0), (13.0, -8.0, 1.0, 0.0),
        (-14.0, 9.0, 1.0, 30.0), (-5.0, 9.0, 1.0, 30.0),
        (4.0, 9.0, 1.0, 30.0), (13.0, 9.0, 1.0, 30.0)), 4.2)
   ```

   上排 yaw 0、下排 yaw 30 —— **这一对比是整个试验的重点**。
   `put` 的第三个参数是变体数，要和 glb 里的网格数一致。
3. 顺手把 `MIN_ROCKS` / `MIN_TREES` 挪到画面边上，别挡住试验品。
4. `bash tools/hr_map_shot.sh out.png`（**不能直接跑 Godot**：
   改了 glb 不重新导入，渲出来还是旧模型）
5. 看完 `git checkout -- styles/hellrider/layout.py` 还原。

## 三个脚本

| | 是什么 | 结果 |
|---|---|---|
| `voxel_test.py` | 均匀小方块堆的树和岩 | 岩在 yaw 0 下读成条纹煎饼；树因为方块往各方向支棱，勉强能看。面数 336–408，贵 |
| `block_test.py` | 大小不一的方盒堆的岩，倒角/不倒角各一份 | yaw 0 仍然不成立，**倒角救不了** —— 顶面全一档、正面全一档，只剩轮廓 |
| `slab_test.py` | **平面轮廓带 30/45/60° 斜边、墙垂直的台地岩** | **yaw 0 成立。** 这是唯一过关的一版 |

`slab_test.py` 的关键做法：轮廓不是随便画的多边形，而是拿**半平面去切一个大方形**，
半平面的法线只从一组固定角度里取 —— 交出来的凸多边形，每条边必然是那几个方向之一。

调出味道的两个数（第一版是"叠盘子"）：

- **厚薄要拉开**：40% 概率做 0.30–0.55 的薄"台沿"，其余 1.1–1.9 的厚"墙"
- **偏心给足**：每层中心偏 ±0.9r，才有"一侧陡、一侧出台沿"的读法
